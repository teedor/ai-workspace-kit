---
name: plain
description: De-jargon a piece of writing. Find hard words, long sentences and assumed knowledge, and make it plain English without losing accuracy. Use when I ask to make something simpler, clearer or less jargony.
---

Make the writing I name (or the current piece) clear for its real reader.
Check `notes/style-guide.md` for who that is, and ask if it isn't clear.
**If the readers are experts** (examiners, engineers, specialists), keep the
technical terms they expect and only fix what's genuinely unclear: long
sentences, vague claims, undefined abbreviations.

1. **List the problems first**, before changing anything:
   - jargon or hard words, each with a plain alternative or a short definition
   - sentences over about 25 words
   - knowledge it assumes the reader already has
   - foggy, passive phrasing ("it was decided that…")
2. Show me the list. Then rewrite, **unless "Rules for this work" in
   `CLAUDE.md` says this is assessed: then stop at the list. I rewrite.**
3. **Simplify the words, never the truth.** If the original said "probably",
   the plain version mustn't say "definitely". Nothing gets more certain by
   getting simpler.
4. Follow `notes/style-guide.md`. Add any new terms to `notes/glossary.md`.
5. If it's a substantial piece, offer to keep both: the full version, plus an
   "explained simply" version saved alongside it.

This works on code too: comments, error messages, README files, and anything
a user will read.
